## Drift

### I1 — Legacy dual-interface bridge (informational)

- **File:** `src/sinks/s3.ts`:36, 84-103
- **Finding:** `S3Sink` implements both `LegacySink` and `SnapshotSink`.
  Legacy payloads are detected via `"session" in payload` and rejected
  with `LEGACY_PAYLOAD_ERROR`. The constructor accepts either
  `LegacySinkConfig` or `SnapshotSinkConfig` via a union type and casts
  to `S3ConfigFields` to extract values.
- **Severity:** Informational. Same pattern as the webhook sink (I1 from
  `2026-04-01-W1-SINK-01-cursor`). Legacy payloads fail loudly, not
  silently. The bridge allows the sink to compile against the existing
  codebase during the v1→v2 transition.
- **Impact:** None. Should be removed when v1 callers migrate.

### I2 — Duplicate default prefix constant (informational)

- **File:** `src/sinks/s3.ts`:13, `src/contracts/config.ts`:8
- **Finding:** `src/sinks/s3.ts` defines `DEFAULT_PREFIX = "jin"` while
  the frozen config defines `DEFAULT_S3_PREFIX = "jin/"`. The
  `normalizePrefix()` function strips trailing slashes, so both converge
  to `"jin"`. No behavioral difference, but the duplication means a
  future change to `DEFAULT_S3_PREFIX` in the frozen config would not
  propagate to the fallback in `s3.ts`.
- **Severity:** Informational. The test overrides prefix explicitly, so
  this does not affect correctness today.
- **Impact:** Minimal. Integration pass should wire the constructor to
  read from the frozen config constant instead of the local one.
