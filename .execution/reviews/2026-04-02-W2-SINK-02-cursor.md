## Findings

### P2: `healthCheck()` misclassifies permission errors on `jin_meta` as "schema not initialized"

- **File:** `src/sinks/postgres.ts`:357-365, 525-534
- **Finding:** `checkSchemaCompatibility()` routes any error text containing
  both `jin_meta` and `relation` through the missing-schema path. That is
  too broad for Postgres: permission failures like
  `permission denied for relation public.jin_meta` also match, so the sink
  reports `Remote schema is not initialized...` instead of surfacing the
  real auth/grant failure.
- **Evidence:** A read-only runtime probe against the current workspace,
  using a mocked `403 permission denied for relation public.jin_meta`
  response, returned:
  `{"ok":false,"error":"Remote schema is not initialized: missing \"public\".\"jin_meta\"."}`
- **Impact:** This breaks the BP-06 schema handshake semantics on a real
  readiness failure mode. Operators will get the wrong remediation
  guidance, and Codex cannot treat the Postgres sink handshake as fully
  correct yet.
- **Fix:** Tighten `looksLikeMissingMetaTable()` to actual missing-table
  signals (`does not exist`, `undefined table`, ideally SQLSTATE `42P01`
  when available) and add a regression test for permission-denied.

### I1: Messages/tool_calls use DELETE+INSERT rather than the BP-06 upsert wire shape

- **File:** `src/sinks/postgres.ts`:121-147, 236-307
- **Finding:** Conversations use `ON CONFLICT` upsert, but messages and
  tool calls are replaced with `DELETE ... WHERE conversation_id = $1`
  followed by plain `INSERT`.
- **Severity:** Informational. The sink still applies a full snapshot per
  conversation and keeps packet acceptance checks green.
- **Impact:** More write churn than upsert, and any remote schema that adds
  dependent row-level behavior on delete would feel this more sharply.

### I2: Minor-version mismatch continues silently

- **File:** `src/sinks/postgres.ts`:338-356
- **Finding:** BP-06 says minor-version mismatch should warn but continue.
  The current code continues, but emits no warning or diagnostic signal.
- **Severity:** Informational. Push behavior is still correct; only the
  operator-facing warning is missing.

### I3: Legacy dual-interface bridge remains in the Postgres sink

- **File:** `src/sinks/postgres.ts`:33, 68-78, 496-509
- **Finding:** `PostgresSink` still implements both the legacy and v2 sink
  interfaces, rejecting legacy payloads with a loud error instead of
  removing the bridge outright.
- **Severity:** Informational. This matches the webhook sink's transition
  pattern and does not silently blur the frozen v2 contract.

## Aligned

### Schema/version handshake core

- The sink reads `schema_version` from `jin_meta` on every
  `healthCheck()` and `push()` readiness check.
  (`src/sinks/postgres.ts`:64-66, 94-97, 316-356)
- Major-version mismatch blocks pushes in both directions, and missing
  table / missing row / empty value all refuse pushes as "not
  initialized." (`src/sinks/postgres.ts`:323-353, 358-362)
- Re-checking on each push means the sink can recover after the remote
  schema is fixed without requiring a process restart.

### No-DDL normal push path

- The packet-owned sink file issues only readiness `SELECT`, transaction
  control, `DELETE`, and `INSERT` statements. No `CREATE`, `ALTER`,
  `DROP`, or provisioning behavior remains in `src/sinks/postgres.ts`.
- The packet test explicitly filters captured queries for DDL and expects
  none. (`test/postgres-reference-sink.test.ts`:99-118)

### Full-snapshot push semantics and result accounting

- `push()` rejects legacy payloads and routes v2 payloads through
  `pushSnapshots()`, which operates on full
  `{ attemptedRevision, conversation, messages, toolCalls }` snapshots.
  (`src/sinks/postgres.ts`:68-78, 89-118)
- The sink attempts every payload in the batch, records per-conversation
  failures, and preserves the invariant
  `pushed + failed === payloads.length`.
  (`src/sinks/postgres.ts`:99-118, 511-523)
- The packet test verifies both per-conversation error reporting and the
  pushed-plus-failed invariant. (`test/postgres-reference-sink.test.ts`:77-118)

### Boundary discipline

- No packet-attributable spread detected beyond `src/sinks/postgres.ts`
- The new coverage is confined to `test/postgres-reference-sink.test.ts`
- `src/sinks/postgres-search.ts` was read as reference context only and
  was not touched by this lane
