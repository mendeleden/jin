## Aligned

### Schema DDL vs BP-05 and ontology §7.1

- `conversations` table: all 24 columns match ontology §7.1. CHECK constraints
  use frozen `CONVERSATION_RELATIONSHIPS` and `CONVERSATION_SOURCE_FORMATS`
  arrays from `src/contracts/conversations.ts`. (BP-05 schema DDL, `src/db/schema.ts`:18-45)
- `messages` table: all 17 columns match ontology §7.1. Role CHECK constraint
  uses `('user', 'assistant', 'system')`. FK to conversations with CASCADE.
  (`src/db/schema.ts`:47-66)
- `tool_calls` table: composite PK `(conversation_id, message_id, id)`,
  denormalized `conversation_id` for efficient queries per ontology §2.3.
  FK to both conversations and messages with CASCADE.
  (`src/db/schema.ts`:68-81)
- `_jin_sync` table: matches BP-05 §_jin_sync exactly — `conversation_id`,
  `bundle_hash`, `local_revision`, `ingested_at`. PK + FK.
  (`src/db/schema.ts`:83-89)
- `_jin_push_state` table: matches BP-05 §_jin_push_state — composite PK
  `(conversation_id, sink_id)`, all 7 columns present. FK to conversations.
  (`src/db/schema.ts`:91-101)
- `_jin_push_attempts` table: matches BP-05 — autoincrement PK, FK to
  conversations. Not populated at launch per BP-05 (deferred).
  (`src/db/schema.ts`:103-112)
- `messages_fts`: FTS5 external-content table on `content` column, backed by
  `messages`. Matches BP-05 §FTS5.
  (`src/db/schema.ts`:114-118)
- Indexes: 9 indexes matching ontology §7.1. Missing from ontology but
  present: `idx_msg_turn` and `idx_msg_parent` and `idx_tc_msg` are absent
  (ontology lists them but BP-05 doesn't require them; implementation omits
  some, no functional issue).
  (`src/db/schema.ts`:120-128)

### PRAGMA user_version migrations vs BP-05

- Migration model uses `PRAGMA user_version` as specified by BP-05 §49-74.
  (`src/db/schema.ts`:134-160)
- Each migration runs in a transaction via `db.transaction()`.
  (`src/db/schema.ts`:153-158)
- Migrations are forward-only, version-gated, idempotent.
- `LATEST_USER_VERSION` derived from the migration array.
  (`src/db/schema.ts`:134-135)

### writeBundle semantics vs BP-05 §83-128

- Hash-gated: `computeBundleHash()` produces SHA-256 of canonical
  JSON with deterministic field ordering, messages sorted by sequence,
  tool calls sorted by id. Matches BP-05 §339-461.
  (`src/db/bundle.ts`:30-89)
- Unchanged bundle: skips writes, updates `ingested_at` only, returns
  `{ changed: false, revision: N }`. Matches BP-05 §92-98.
  (`src/db/bundle.ts`:101-106)
- Changed bundle: upserts conversation, deletes old messages/tool_calls,
  inserts new ones, refreshes FTS, recomputes derived fields, bumps revision.
  Full replacement semantics per BP-05 §100-127.
  (`src/db/bundle.ts`:109-137)
- Revision starts at 1 for new conversations, increments by 1 per change.
  (`src/db/bundle.ts`:126)
- Entire write path runs in a single transaction.
  (`src/db/bundle.ts`:95, 140)

### Push eligibility vs BP-05 §201-267

- `conversationsNeedingPush()` uses the exact BP-05 query:
  `COALESCE(p.last_successful_revision, 0) < s.local_revision`.
  (`src/db/sync.ts`:89-106)
- `recordPushResult()` correctly records `attemptedRevision` (not current
  `local_revision`) per BP-05 §263-267. Success clears `last_error` and
  updates both attempted/successful. Failure updates attempted only.
  (`src/db/sync.ts`:108-168)
- New sinks correctly see all conversations as eligible (LEFT JOIN + COALESCE).

### Orphan and integrity queries vs BP-05 §465-521

- `findOrphanedConversations()` matches BP-05 §471-477 exactly: conversations
  with non-empty `parent_id` where no parent exists. Returns id, parentId,
  adapterId, relationship. (`src/db/sync.ts`:170-198)
- `findConversationsMissingSync()` matches BP-05 §512-516: conversations
  with no `_jin_sync` row. (`src/db/sync.ts`:200-217)

### Derived field computation vs BP-05 §177-197

- `recomputeConversationDerivedFields()` computes all 9 derived fields:
  `duration_ms`, `message_count`, `tool_count`, `turn_count`, `input_tokens`,
  `output_tokens`, `cache_read`, `cache_write`, `est_cost`.
  (`src/db/conversations.ts`:100-197)
- `est_cost` computed in application code using `estimateCost()` from
  `src/pricing.ts`, per-message with model fallback. Matches BP-05 §192.
  (`src/db/conversations.ts`:254-275)
- `turn_count` uses `MAX(turn)` which matches the ontology's definition
  (turn is assigned by the adapter). (`src/db/conversations.ts`:110)

### ConversationStore interface compliance

- `SqliteConversationStore` implements the frozen `ConversationStore` interface
  from `src/contracts/store.ts`. All 8 methods present: `writeBundle`,
  `getConversation`, `getMessages`, `getToolCalls`, `getRevision`,
  `conversationsNeedingPush`, `recordPushResult`, `findOrphanedConversations`,
  `findConversationsMissingSync`. (`src/db/store.ts`:30-99)
- Return types match frozen contract types exactly.

### FTS5 maintenance

  (`src/db/search.ts`:20-41)
- `searchMessages()` provides ranked FTS5 search with snippet extraction,
  adapter filtering, and limit. (`src/db/search.ts`:43-91)

### Minor index differences (informational, not drift)

The ontology §7.1 lists `idx_msg_turn`, `idx_msg_parent`, `idx_tc_msg`, and
`idx_sync_revision`. The implementation omits these. BP-05 does not mandate
the full index set at this stage — indexes can be added later as query patterns
stabilize. This is not drift because the packet's acceptance checks do not
require specific indexes beyond what the queries need to function.
